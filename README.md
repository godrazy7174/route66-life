# 66번 국도 — 서부 인생게임

오버워치 2 워크샵 모드. 데드록 협곡을 무대로, 일을 구해 돈을 벌고 장비와 사업을 마련해
마을을 재건하고 새 출발의 기차에 오르는 생활 시뮬레이션. 최대 8인.

공개 위키: https://route66-life-wiki.ray-on.chatgpt.site

---

## 0. 다른 PC에서 이어서 작업할 때

이 문서는 **맥락 없이 처음 이 폴더를 여는 사람(또는 AI)에게 넘기는 인수인계서**다.
코드만 봐서는 알 수 없는 결정과 함정을 담았다. 손대기 전에 3·4·5장을 읽어라.
이어서 할 일은 7장에 있다.

필요한 것: Python 3, (위키 작업 시) Node/npm + Codex CLI + ChatGPT 로그인.

저장소 (비공개):

| 용도 | 주소 |
|---|---|
| 게임 | `github.com/godrazy7174/route66-life` |
| 위키 소스 | `github.com/godrazy7174/route66-life-wiki` |
| 위키 작업 지시서 | `github.com/godrazy7174/route66-life-tasks` |

위키 소스 저장소는 코덱스 샌드박스 계정이 만든 것이라 clone 후
`git config --global --add safe.directory <경로>` 가 필요할 수 있다.

클라우드 세션(「레포 선택」)으로도 이어갈 수 있지만 **대화는 옮겨지지 않는다.**
새 세션은 언제나 맥락 0에서 시작하므로 이 문서가 유일한 인계 수단이다.
컨테이너에서 되는 것은 `.ow` 수정 · 검사기 6종 · `to_korean.py` · `sim_*.py` · git 이고,
**위키 배포는 안 된다** (Codex CLI 와 ChatGPT 로그인이 없다).

## 1. 파일 지도

| 파일 | 역할 |
|---|---|
| `ROUTE66_LIFE_EN.ow` | **진실 원본.** 모든 수정은 여기에 한다 |
| `ROUTE66_LIFE.ow` | 한국어 클라이언트용 산출물. **직접 고치지 말 것** (매번 재생성됨) |
| `to_korean.py` | EN → KO 변환기 |
| `lint.py` | 주 검사기 (20개 항목). **깨끗한 파일에서는 `!!` 가 하나도 나오지 않는다** — `!!` 는 전부 진짜 신호다 |
| `blockcheck.py` | If/For/While ↔ End 균형 |
| `enumcheck.py` | 변수 색인 중복·범위 |
| `paircheck.py` | 엔티티 생성/파괴 짝 |
| `labelcheck.py` | 구역 라벨 정합성 |
| `ref/` | 워크샵 요소 정의(OverPy). **lint가 읽으므로 필수** |
| `patch*.py` | 적용 이력. 각 패치 상단 docstring에 "왜 고쳤는가"가 있다 |
| `sim_*.py` | 세이브 코드·경제 시뮬레이터 |

## 2. 수정 파이프라인

```bash
python lint.py ROUTE66_LIFE_EN.ow
python blockcheck.py ROUTE66_LIFE_EN.ow
python enumcheck.py ROUTE66_LIFE_EN.ow
python paircheck.py ROUTE66_LIFE_EN.ow
python labelcheck.py ROUTE66_LIFE_EN.ow
python to_korean.py ROUTE66_LIFE_EN.ow ROUTE66_LIFE.ow
```

여섯 개가 전부 통과해야 게임에 임포트한다. 수정은 `patch*.py` 스크립트로 하고
(앵커 문자열 + `assert count == 1`), 스크립트 상단에 이유를 남긴다.
직접 편집하면 왜 그렇게 됐는지가 사라진다.

**균형 수치를 바꿀 때는 `sim_economy.py` 로 근거를 만든다.** 이 시뮬레이터는
상수를 `.ow` 에서 직접 읽고 좌표 풀로 실제 거리 분포를 뽑은 뒤, **피로를 제약으로 넣어**
지속 시급을 계산한다 (숙박 $90 = 피로 40 이므로 피로 1 = $2.25). 피로를 빼면 순위가 뒤집힌다 —
채굴은 순진 계산으로 2위($568/분)지만 피로를 넣으면 4위($159/분)다.

## 3. 워크샵 한도 (넘으면 임포트가 거부된다)

- **규칙 하나의 텍스트 약 40KB**가 실질 병목. 넘으면 규칙을 쪼갠다
  (`[조작 03a]`~`[조작 03f]`가 그렇게 갈라진 것)
- **플레이어 변수 128칸 — 이미 꽉 찼다.** 새 변수가 필요하면 기존 변수를 겸용하거나
  자릿수 패킹을 쓴다. 예: `Giant`는 1의 자리 = 오늘의 계약 진행도, 10의 자리 = 마스터리
- **전역 변수 128칸** (현재 77)
- **Custom String은 128자를 넘으면 잘려서 렌더링**된다 (lint가 검사)
- **Custom String의 형식 인자는 최대 3개**(`{0}`~`{2}`). 더 필요하면 문자열을 중첩한다 (lint가 검사)

## 4. 실기에서만 드러난 함정 — 전부 실제로 당한 것들

1. **`Random Value In Array(빈 배열)`은 0을 돌려주고, 0은 좌표 (0,0,0)이 된다.**
   이벤트가 맵 원점이나 발밑에 생기면 십중팔구 이것. 배치는 반드시
   **검증된 좌표 풀(`SpotPos` = 사람이 직접 걸어 찍은 28지점)**에서만 뽑는다.
   좌표를 *계산*하지 마라 — 협곡에서는 오프셋이 허공이나 절벽 안으로 간다.
   (`Nearest Walkable Position`도 벽 사이 도달 불가 지점을 잡는다)

2. **`Ongoing - Each Player` 룰은 같은 프레임에 여러 인스턴스가 뜬다.**
   전역 상태를 선착순으로 낚아채는 액션(보물 상자, 대사냥 각성)은
   **액션 시작 시점에 조건을 다시 확인**해야 한다. 조건 블록만으로는 못 막는다.

3. **Ongoing 룰은 조건이 false→true로 바뀔 때만 발동한다.**
   그래서 액션이 자기 조건 변수를 껐다 켜면(`Busy` 1→0) 버튼을 누른 채로 **연타**된다.
   그런 룰 끝에는 `Wait Until(Not(Is Button Held(...)), N)`을 붙인다.

4. **빈 `Else` 뒤에 `Else If`를 쓰면 그 뒤는 영영 실행되지 않는다.** (lint가 검사)

5. **`Phased Out`은 무기 피해만 막는다. 스크립트 `Damage()`는 그대로 통과한다.**
   PvP 피해를 스크립트로 준다면 표적 필터에서 `Has Status(..., Phased Out) == False`를
   빼먹지 마라 — 튜토리얼·유치장·취침 중인 사람이 맞는다.

6. **더미 봇은 `Init`이 0이다** (`[코어 03]`이 봇을 건너뛴다). 봇 배제 조건으로 쓰면 편하다.

7. **게이트 플래그(`Ready`)는 월드 구축이 끝난 뒤에 켠다.** 먼저 켜면
   `SpotPos`가 비어 있고 `LocPos` 보정이 안 끝난 상태로 24개 룰이 깨어난다.

8. **엔티티 핸들은 반드시 변수에 담고, 이탈 시 정리한다.**
   `Player Left Match`가 없으면 나간 사람의 표식·효과가 맵에 영영 남는다 (`[코어 11]`).

9. **플레이어별 HUD를 만들지 마라.** `Create HUD Text(Event Player, ...)`를 플레이어마다
   만들면 핸들이 없어 파괴할 수 없고 이탈 시 누수된다.
   `Ongoing - Global` + `Local Player` 조건으로 **전역 1개**를 만든다 (`[코어 08]`, `[알림 01]`).

10. **`to_korean.py`의 `SETTINGS_KO`는 하드코딩이다.** EN 쪽 로비 설정을 바꿔도
    자동 반영되지 않는다 (지금은 교차검사가 있어 불일치를 잡아준다).

11. **한국어 클라이언트는 영웅 이름을 번역해야 한다.** `to_korean.py`의 사전에 없는 영웅이
    영문으로 남으면 임포트가 거부된다 (미번역 영웅 검사 있음).

12. **`Sorted Array(Filtered Array(...))`는 정상 동작한다.** 한때 이걸 의심했는데
    재산 순위·강탈 조준이 이 패턴으로 잘 돌아간다. 배치 버그의 진범은 따로 있었다(1번).

13. **서브루틴 안의 `Abort` 는 호출한 룰의 남은 액션까지 멈춘다.**
    정의가 "Stops execution of the action list" 이고, `Call Subroutine` 은 인라인 실행이다.
    그래서 `Call Subroutine` 뒤에 둔 뒷정리는 그 서브루틴이 Abort 하면 건너뛴다.

14. **`Local Player` 는 시각/HUD 액션에서만 접근 가능하고 변수에 저장할 수 없다.**
    대신 `Ongoing - Global` 룰에서 써도 되므로, 플레이어별 HUD 대신 전역 1개로 만들 수 있다.

15. **3번(버튼 홀드 재발동)은 서브루틴을 건너뛰어 일어난다.** `[조작 03a]` 는 디바운스가
    없는데 `DoMine` 에는 있어서 안전해 보였지만, 같은 룰이 부르는 `DoSleep` 에는 없어
    F 를 누르고 있으면 4.5초마다 $90 씩 자동으로 다시 잤다.
    디바운스는 **토글이 실제로 일어나는 그 룰**에 둬야 한다 (lint 가 경로별로 검사한다).

16. **한 변수를 Icon 과 Effect 양쪽으로 쓰는 곳이 있다.** `EscortFlash` 가 그렇다 —
    `[호송]` 에서는 아이콘 핸들을, `[목동]` 의 늑대에서는 붉은 구체 이펙트 핸들을 담는다.
    그래서 `[코어 11]` 은 `Destroy Icon` 과 `Destroy Effect` 를 **둘 다** 부른다.
    중복처럼 보이지만 지우면 한쪽이 샌다. (`DialTgt`·`DialPin`·`DialCur` 도 활동마다 겸용된다 —
    변수 128칸이 꽉 차서 생긴 구조다. 겸용 변수를 건드릴 때는 쓰는 곳을 전부 찾아라.)

17. **룰 조건을 추가해도 이미 돌고 있는 `Loop If` 인스턴스는 멈추지 않는다.**
    `ref/actions.ts` 의 정의가 "Restarts the action list from the beginning if
    **this action's condition** evaluates to true" 라, `Loop If` 는 자기 인자만 본다.
    룰의 conditions 블록을 다시 보는 것은 별개 액션 `Loop If Condition Is True` 다.
    게다가 `Wait(..., Ignore Condition)` 은 "the wait will not be interrupted" 라
    조건이 거짓이 되어도 중단되지 않는다. 그래서 배제 조건은
    **conditions 와 `Loop If` 양쪽에** 넣어야 한다.
    `[직업 03-3] 야수 배회` 에서 실제로 당했다 — 대야수를 배제하려고 conditions 에만
    조건을 넣었더니 이미 돌던 배회 루프가 계속 살아, 11m 리쉬 순간이동과 무작위 throttle 로
    `[대사냥 06]` 의 추격을 매 틱 무력화했다. 도달 경로도 평범하다: `[직업 02] DoHunt` 의
    Abort 가드는 `HuntPhase == 4` 일 때만 걸리므로 흔적 조사 단계에서 야수에
    `RevealEnd = +50` 이 붙고, 그 50초 안에 3번째 흔적을 조사하면 `[대사냥 02]` 가
    `RevealEnd` 를 보지 않고 그 봇을 대야수로 집은 뒤 `RevealEnd` 를 `+9999` 로 덮는다.
    **검사기 6종 어디에도 걸리지 않는다.**

## 4-1. 알고 있는 잔재 (버그 아님)

- **`ArchOn` 전역은 0에서 변하지 않는다.** 제거된 '건축' 기능의 흔적으로,
  16개 룰이 `ArchOn == 0` 을 조건으로 갖고 있지만 1이 되는 곳이 없어 항상 통과한다.
  기능에는 영향이 없어 그대로 뒀다 — 조건 16개를 건드리는 것이 얻는 것보다 위험하다.
  **다만 그 전역 슬롯을 재사용하지 마라.** 누군가 1을 넣는 순간 16개 룰이 조용히 잠긴다.
- **`paircheck.py`는 변수 단위로만 본다.** 같은 변수의 `Destroy` 가 다른 곳에
  하나라도 남아 있으면, 특정 지점의 `Destroy` 누락은 잡지 못한다.

## 5. 바뀌지 않는 설계 결정

- **NPC 무법자 영구 금지.** 범죄의 상대는 언제나 사람이다
- **정치 시스템 영구 제외**
- 캐서디/애쉬로 시작 → 가죽 배낭이면 트레이서, 말이면 시온, 현상금 사냥꾼이면 프레야
- **좌클릭 사격만.** 영웅 스킬은 전부 봉인. 탄창은 999발로 늘려 재장전 자체가 없다
- **일하면 그 직업이 된다** (자동 전직). 별도 전직 창구 없음
- **최대 8인.** 2팀 4칸을 야수 3 + 쥐 1이 쓴다
- 모든 직업은 "무지성 반복은 실패하고, 공략을 익히면 깨는" 문법을 따른다
- **위키 작업은 코덱스에 위임한다** (아래 6장)

## 6. 위키

소스는 별도 저장소 `route66-wiki`. 배포는 코덱스가 한다:

```bash
codex exec --cd <route66-wiki 경로> --approve-for-me "$(cat codex_task_wiki_updateN.md)"
```

작업 지시서(`codex_task_*.md`)에 **바꿀 절 id와 정확한 문구**를 적는다.
지시한 절만 고치므로, 같은 사실이 FAQ 등 다른 곳에도 적혀 있으면 함께 지정해야 한다.
배포 후에는 반드시 **라이브 페이지를 다시 읽어 반영을 확인**한다.

> 코덱스 실행 로그(`*.log`)에는 배포 토큰이 남는다. `.gitignore`로 제외되어 있다.

> 코덱스의 Windows 샌드박스가 이따금 자식 프로세스를 못 띄운다
> (`CreateProcessAsUserW failed: 5`). 이때는 명령을 한 줄도 실행하지 못한 채 종료하므로
> **결과를 반드시 확인해야 한다** — 성공한 것처럼 조용히 끝난다. 그냥 다시 실행하면 된다.

## 7. 아직 실기로 확인하지 않은 것

정적 검사로는 잡히지 않아 게임 안에서만 확인되는 것들. 위험한 순서다.

혼자서 되는 것 (`ROUTE66_LIFE.ow`):

1. **밀수 접선지 · 금괴 호송 목적지** — 맵 원점(0,0,0)이나 발밑에 뜨지 않는지, 걸어서 닿는지.
   각 5회 이상. 배치 버그(4장 1번)의 진범을 잡은 것이 최근이라 여기가 최우선이다.
2. **대사냥 봉인** — 대야수 발현 중 「흔적 추적」이 막히고, 토벌하거나 밤이 오면 **즉시** 풀리는지.
   3회 조사 단계에서는 막히면 안 된다.
3. **무한 탄창** — 캐서디·애쉬·트레이서·시온·프레야 전부 재장전이 사라졌는지
   (영웅마다 무기 슬롯이 달라 한 영웅만 확인하면 부족하다).
4. **급행 우편** — 솔로에서 배달 수주 뒤 7~14초 안에 뜨는지, 기한 안에 닿으면 보수가 2배인지.
5. **밀수 쿨타임** — 인계 직후 재수주를 시도해 안내 문구의 남은 초가 30에서 시작하는지.
6. **술집 도박 · 잡화점 메뉴** — F 를 누른 채로 도박이 연타되지 않는지,
   R 로 3번째 항목(원석·가죽 판매)에 닿는지.
7. **유치장 사망** — 갇힌 채 죽고 부활했을 때 이동과 사격이 돌아오는지.
8. **대야수 추격·강타** (8-2) — 대야수가 사람을 쫓아오는지, 강타가 들어오는지.
   **사거리는 25 → 12 → 15, 피해는 55 → 28 로 이미 조정했다(8-6).**
   바꿀 때는 강타 판정과 끼임 순간이동 조건 **두 곳을 같이** 고쳐야 한다 —

### 8-3. 끝난 것 — 쥐 행동 개편 (`patch_rat_behavior.py`)

**사용자 결정: 육포를 먼저 털고, 육포가 없으면 죽거나 사람을 잡을 때까지 안 사라진다.
솔로 소프트락을 막기 위해 「인원수만큼 약해지게」.**

만든 것: `[쥐 02]` 우선순위를 뒤집어 `JerkyStock > 0` 이면 잡화점 직행(가는 길 3.5m 안의

신규 룰이 `RatKill` 을 세운다. `[쥐 05]` 의 피해 배율을 인원에 비례시켜

**표적 필터에 `Phased Out` 을 추가했다** — 명세에 없지만 4장 5번대로 스크립트 `Damage` 는
`Phased Out` 을 뚫는다.

만들기 전의 상태(참고):

- `[쥐 01]` 이 45초 뒤 **무조건** 철수하며 육포 15 를 깎는다.
- `[쥐 02]` 는 **사람을 먼저 쫓고**, 잡화점(`LocPos[2]`) 9m 안에 있을 때만 육포를 2씩 턴다.
- `[쥐 03]` 이 `Set Damage Received(rat, Count(RatHitters) >= 3 ? 70 : 18)` 로
  **타격자 3명 이상이면** 쥐가 약해지게 한다. 쥐는 667 체력이라 18% 면 실효 3,705.

만들 것:

1. **육포 우선** — `[쥐 02]` 를 뒤집는다. `JerkyStock > 0` 이면 잡화점으로 직행하고
   (가는 길에 3.5m 안의 사람은 문다), `JerkyStock == 0` 이 되어서야 사람을 사냥한다.
2. **지속** — `[쥐 01]` 의 `Wait(45)` 뒤에 `JerkyStock == 0` 이면 물러나지 않게 한다.
   `Wait Until(Or(RatOn == 0, RatKill == 1), 99999)` 로 **죽거나 사람을 잡을 때까지** 남긴다.
   물러나지 않는다는 것을 Big Message 로 알릴 것.
3. **중복 방지** — `[쥐 01]` 의 `RatOn == 0` 조건이 **이미** 막고 있다.
   다음 일정이 와도 대기열에 쌓이지 않고 그냥 건너뛰며, 쥐가 죽을 때 `[쥐 04]` 가
   `RatNext` 를 다시 잡는다. **동작은 이미 맞으니 확인만 하고 문서화하면 된다.**
4. **인원 비례 난이도** — `[쥐 03]` 의 값을
   `Max(Count Of(RatHitters) >= 3 ? 70 : 18, Divide(54, Max(1, 접속 인원)))` 로 바꾼다.

   접속 인원은 `Count Of(Filtered Array(All Players(Team 1), And(Is Alive, Init == 1)))`.
5. 신규 전역 예정: `RatKill`.
   신규 룰 예정: **`[쥐 06] 쥐가 사람을 잡았다`** (`Player Died` / Team 1,
   공격자가 Team 2 슬롯 3 봇이면 `RatKill = 1`). 습격 시작 시 `RatKill = 0` 으로 초기화.
6. **같이 지울 잔재** — `[쥐 01]` 의 `Set Global Variable(RatNext, Add(Total Time Elapsed(), 240))`
   은 바로 아래 줄에서 `Random Real(240, 600)` 으로 덮어써지는 죽은 코드다.

### 8-4. 구현하며 드러난 것

**위 8-3 명세 자체에 오류가 둘 있다. 위 문장은 지시 원본이라 그대로 두고 여기에 적는다.**

- **항목 4 의 룰 번호가 틀렸다.** `Set Damage Received` 공식은 `[쥐 03]` 이 아니라
  **`[쥐 05] 쥐떼의 가죽`** 에 있다. `[쥐 03] 사냥꾼의 이빨` 은 직업 보정 피해 룰이다.
  의도(피해 배율)를 따라 `[쥐 05]` 를 고쳤다.
- **항목 4 의 실효 체력 「3,705 → 1,235」 가 6배 어긋난다.** `Set Max Health` 는 백분율이고
  `patch157_ratgate.py` 주석대로 쥐 체력은 667 이 아니라 약 4,000 이다.
  실제로는 18% → 22,233 / 27% → 14,822 / 54% → 7,411 이다.
  상대 효과(솔로 3배 완화)는 그대로 성립하나, **절대 난이도가 솔로에서 성립하지 않았다.**
  54% 면 4000 / 0.54 = 7,411 을 넣어야 하는데 캐서디 지속 화력 약 120/초로 **62초**다.
  쥐는 3.5m 안에서 초당 20 을 물고 이동 속도 130 으로 걷기(100)보다 빠르니
  플레이어는 10초 남짓에 죽는다 — 사실상 못 잡는다.
  **`patch_rat_solo_balance.py` 로 재조정했다 (아래 8-5).**

**파생 수정 — 쥐 첫 습격이 게임 시작과 동시에 터졌다 (`patch_rat_firstdelay.py`).**
`RatNext` 와 `RatOn` 이 어디서도 초기화되지 않았다. 워크샵 전역 기본값은 0 이라
`[쥐 01]` 의 세 조건이 `Ready = 1` 되는 프레임에 동시에 참이 된다 — 환영 메시지와 같은 프레임이다.
8-3 이전부터 있던 동작이지만 8-3 이 대가를 키웠다: `JerkyStock` 15 가 초당 2 씩 깎여 약 8초면
0 이 되고, 그러면 버티기가 발동하는데 시작 직후에는 전원이 튜토리얼이라 `TutOn == 1` 로
표적에서 걸러진다. `RatKill` 이 영원히 서지 않아 쥐가 무한정 상주한다.
`[코어 01]` 에서 `RatNext` 를 습격 간격과 같은 `Random Real(240, 600)` 으로 잡아 해결했다.

> **아직 남은 구조적 문제.** 「표적이 아무도 없으면 버티기가 안 풀린다」는 그대로다.
> 전원이 유치장에 있거나 늦게 들어온 사람이 튜토리얼 중이면 같은 상황이 다시 생긴다.
> 실기에서 문제가 되면 「표적이 없으면 버티기 해제」 안전장치를 넣어라.

### 8-5. 쥐 솔로 난이도 재조정 (`patch_rat_solo_balance.py`)

**`X / N` 꼴로는 분자를 키워도 해결되지 않는다.** TTK = 체력 x 100 / (X x 1인당 화력)
이라 **N 이 약분되어 TTK 가 인원수와 무관**하다. 분자를 키우면 모든 인원수가 같은 비율로
쉬워져 3인 이상 구간의 설계(기본 18%, 타격자 3명이면 70%)가 함께 무너진다 —
X=110 이면 18% 바닥이 N>=7 에서야 걸려 3~6인 서버의 "셋은 붙어야 한다"가 사라진다.

그래서 **완화를 3인 미만으로 가뒀다.**

    Max(RatHitters >= 3 ? 70 : 18, RatPop >= 3 ? 0 : Divide(110, Max(1, RatPop)))

| 인원 | 받는 피해 | 필요 총 피해량 | 대략 TTK |
|---|---|---|---|
| 1명 | 110% | 3,636 | 약 30초 |
| 2명 | 55% | 7,273 (둘이 나눔) | 약 30초 |
| 3명 이상 | **손대지 않음** (18%, 타격자 3명이면 70%) | 22,233 / 5,714 | 약 62초 / 16초 |

`RatPop >= 3` 이면 둘째 인자가 0 이 되어 `Max` 가 기존 값을 그대로 고른다.
타격자 게이트의 보상(약 2배)도 그대로다. 솔로·듀오만 30초짜리 카이팅 숙제가 된다
(질주 165 로 쥐 130 을 뿌리치되 기력을 쓴다).

인원 집계에 **`TutOn == 0` 을 추가**했다. 튜토리얼 중인 사람은 싸울 수 없고
`[쥐 02]` 의 표적 필터도 `TutOn == 0` 을 요구하므로, 집계에만 넣으면 쥐만 단단해진다.

전역 88: `RatPop`.

> 위 TTK 는 캐서디 지속 화력을 약 120/초로 잡은 계산값이다. **실기 확인 대상이다** —
> 7장에 넣었다. 30초가 길게 느껴지면 110 을 키우고, 3인 이상은 건드리지 말 것.

### 8-7. 실기 패치노트 7건 (`patch_prices.py` · `patch_fireworks_rumor.py` · `patch_rat_pathing.py` · `patch_perf_scope.py`)

**1 — 쥐 길찾기.** `Start Throttle In Direction` 은 **길찾기가 없는 직선 돌진**이다.
벽이 있으면 밀어붙여 마찰로 멈춘다. 끼임 탈출이 `JerkyStock > 0` 일 때만 있어
**플레이어를 쫓는 동안에는 탈출 수단이 아예 없었다.** 두 갈래로 고쳤다 —
스폰을 협곡 개활지(`LocPos[6]`)에서 **잡화점(`LocPos[2]`)** 으로 옮겨 횡단 자체를 없애고,
`[대사냥 06]` 과 같은 끼임 감지(1초 간격, 1m 미만 x 3틱 -> 목적지 최근접 `SpotPos` 워프)를
**두 갈래 모두에** 넣었다. 목적지를 `RatGoal` 하나로 모아 이동·끼임이 같은 값을 본다.

**3 — 불꽃놀이.** `Play Effect` 는 **지속 시간이 없는 순간 효과**다. 구매 즉시 3발이
터지고 끝나므로 술집 밖으로 나갔을 땐 이미 없다. 게다가 터지는 자리가 **구매자 머리 위**라
실내 천장에 가렸다. `[축제 02]` 로 분리해 **4초 뒤(밖으로 나갈 시간) 술집 상공 34~48m 에서
20발**을 0.45~0.85초 간격으로 터뜨린다. `While` 로 돈다 — `Loop If` 는 목록을 처음부터
다시 돌아(4장 17번) 준비 구간이 매 발 반복된다. **하얀색은 쓰지 않는다**(낮 하늘에 묻힌다).

**4 — 술집 소문.** 버그가 아니라 범위 문제였다. 소문은 `EventKind`(주기적 세계 이벤트)만
읽었고 그 0번이 "오늘은 조용하다"다. 열차·대사냥·쥐를 **아예 보지 않았다.**
우선순위를 두었다 — 발파 준비됨 > 열차의 날 > 대사냥 > 쥐떼 > 주기 이벤트 > 조용하다.
화약을 심어두면 "누가 철길목에 손을 댔다"가 떠, 심은 자만 아는 정보가 **술집에서 살 수 있는
정보**가 된다 (금고 앞 눈치 싸움의 재료).

**6 — 금고 구체.** `[열차 02]` 가 구체 3개를 `TrainFx` 에 담고 **종료 시점에만** 일괄
파괴해서, 하나를 털어도 셋이 남았다. `[열차 03]` 에서 `TrainVault` 를 줄인 **직후**
`TrainFx[TrainVault]` 를 파괴한다 — 3->2 면 인덱스 2, 2->1 이면 1 이 사라져 개수가 일치한다.

**7 — 서버 부하.** 프레임 예산을 먹는 것은 **룰 인스턴스 수 x 조건 평가**다.
`Ongoing - Each Player` 92개 중 **85개가 팀을 `All`** 로 잡아 2팀 봇 4기에도 인스턴스가
생기고 있었다. 그런데 그중 **73개는 조건에 이미 `Is Dummy Bot == False` 나 `Init == 1` 이
있어 봇에서는 절대 통과하지 못한다** — 봇 4기 몫의 평가가 처음부터 전부 헛일이었다.
그 73개를 `Team 1` 로 좁혔다.

    1,104 인스턴스 -> 756 (약 32% 감소)

**동작은 한 글자도 바뀌지 않는다.** 지금도 봇에서 통과하지 못하므로 평가를 안 할 뿐이다.
조건 줄은 그대로 뒀다 — 지우면 테스트 빌드(1팀에 봇을 세운다)와 의미가 달라진다.

> **이걸로 부족하면 다음 레버는 대야수의 30배 크기다.** `ref/actions.ts` 의

### 8-8. 그림자 속도 · 시세 변동 · 크래시 재발 대책 (`patch_shadow_speed.py` · `patch_price_swing.py` · `patch_load_spike.py`)

- **그림자 강도** 접근 6.8 -> 8.0 m/s (0.25초당 1.7 -> 2.0). 질주(약 9.1 m/s)에 바짝
  붙어 도망만으로는 못 떨친다 — 세 발을 쏴야 한다는 설계가 선명해진다.
- **시세 변동성** — 원석 2~5 -> **1~6**, 가죽 3~6 -> **1~8**. **평균은 그대로**(3.5 / 4.5),
  폭만 키웠다. 평균까지 오르면 광부·사냥꾼 기대 수입이 변해 경제 균형이 같이 움직인다.
  1일차 개장가(2/5)는 유지.
- **크래시 재발 — 경고 없이 죽은 이유.** 기존 `[코어 10]` 은 `Server Load()`(순간값) 가
  230 을 **2초 내내** 유지해야 자막을 띄웠다. "과도하게 불러와" 종료는 프레임 하나가
  예산을 터뜨리는 **스파이크형**이라 구조적으로 못 잡는다 — 경고가 안 떴다는 것이
  곧 스파이크형이라는 증거다.
  - **원인 제거**: `ref` 가 명시한 대형 플레이어 부하 — **전설의 야수(50배)가 벽 충돌을
    켠 채** 배회의 무작위 throttle·점프로 협곡 벽을 매 프레임 긁고 있었다 (대야수 30배는
    이미 껐는데 이쪽만 남아 있었다). 발현 확률이 낮아 "이따금, 경고 없이" 와 재현 양상이
    맞는다. 50배를 세울 때 `Disable Movement Collision With Environment(_, False)`,
    되돌리는 세 곳(리롤 Else · 은신 · 처치) 전부에서 `Enable` 복원.
  - **감지 개선**: 조건을 `Server Load Peak() > 200`(최근 최고치 — 스파이크가 지나간
    뒤에도 남는다)으로, 2초 확인 대기 제거. 해제는 Peak < 170.
  - **한계**: 프레임 하나로 즉사하는 최악의 스파이크는 어떤 스크립트도 자막을 못 띄운다.
    경고는 조기 신호일 뿐, 근본 대책은 원인 제거다. **다음 크래시가 또 나면 그때
    대야수/전설 크기 자체(30/50배)를 줄이는 것이 마지막 레버다.**

### 8-6. 대야수 실기 조정 (`patch_beast_tune.py`)

실기 제보로 **사거리 25 → 12, 강타 55 → 28** 로 내렸다.
**12 는 몸집에 딱 붙어야만 맞는 느낌이라 다시 15 로 올렸다 — 현재 값은 15 다.**

야수는 `Hero(Jetpack Cat)` 이고 원래 히트박스가 아주 작은 영웅이라 30배를 해도
몸 반경이 10m 안팎이다. 25m 면 몸 바깥으로 15m 쯤 떨어져 있어도 맞아
"닿지도 않았는데 맞는다"는 체감이 된다. 몸집에 붙는 12 로 내렸다.

> 배율 참고 — 일반 야수 1배 / 거대한 야수 2.4배 / **대야수 30배** / 전설의 야수 50배.
> 대야수는 전설의 야수보다 **작다.**

**사거리는 반드시 두 곳을 같이 고쳐야 한다.** 강타 판정만이 아니라 끼임 워프의
게이트로도 같은 숫자가 쓰인다. 강타만 12 로 내리고 워프 게이트를 25 로 두면
표적이 15~25m 에 있을 때 때리지도 못하고(15 초과) 워프하지도 못해(25 이하)
그 자리에 굳는다.

피해 28 은 1.6초 간격 그대로라 초당 약 17.5 다.
